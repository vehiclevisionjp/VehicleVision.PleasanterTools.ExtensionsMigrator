# リリース手順

## 版

版の単一情報源は `Directory.Build.props` の `VersionPrefix`。セマンティックバージョニングに従い、1.0.0 未満は互換を保証しない。

## 手順

1. `develop` で `VersionPrefix` を上げ、`master` へ PR を出してマージする
2. Actions の「リリースタグ作成」（`release-run.yml`）を `master` から実行する。最初は `dry_run` のまま版だけを検証する
3. 問題なければ `dry_run` を外して実行する。必須チェックの成功を確認してから、GitHub App のトークンで `vX.Y.Z` タグを作る
4. タグを契機に「Release」ワークフロー（`release.yml`）が、検証、配布 ZIP と SHA-256 の作成、GitHub Releases への公開（`publish`）と nuget.org への公開（`publish-nuget`）を行う

`vX.Y.Z-rc.1` のようにハイフン付きの版はプレリリースとして公開する（GitHub Release は `--prerelease`、nuget.org もプレリリースの版になる）。

**初回は `v0.1.0-preview.1`**（#38）。`release-run.yml` の `release_tag` に `v0.1.0-preview.1` を指定する。
`scripts/release-check.ps1` は `VersionPrefix` が `0.1.0` のままで、プレリリースのタグ（`v0.1.0-preview.1`）を通す。

patch 更新だけが溜まったときの自動リリース（旧 `patch-release.yml`）は止めた（#39）。nuget.org に出した版は取り消せないため、リリースは必ず人が `release-run.yml` を起動する。

## NuGet（dotnet tool）の配布

CLI を **dotnet tool** として nuget.org へ配布する（形は #17、公開の処理は #39）。
`release.yml` に公開の処理（`publish-nuget`）を入れた。**タグを push するまで nuget.org へは何も出ない。まだ公開した版は無い。**

| 項目 | 値 |
| --- | --- |
| パッケージ ID | `VehicleVision.PleasanterTools.ExtensionsMigrator`（CLI のアセンブリ名と同じ） |
| コマンド名 | `extensions-migrator`（`ToolCommandName`） |
| 形 | RID 非依存（framework-dependent）の単一パッケージ。**.NET 10 ランタイムが要る** |
| 含めるもの | CLI と Engine の実行物、DotNetClient の DLL（`VehicleVision.PleasanterTools.DotNetClient` 0.2.0。LGPL／AGPL／商用の 3 層・自社。ツールの出力へ含まれる）、README・LICENSING.md・LICENSE・LICENSE-COMMERCIAL.md・NOTICE。pdb は含めない。nuspec に NuGet の依存パッケージは書かれない。DotNetClient の LGPL 全文（COPYING）の同梱は未決定（#38 の判断 2。MailIngest と同じ。判断を待つ） |
| Engine | 別パッケージにしない（`IsPackable=false`）。CLI の出力に含まれる |
| GUI | 作らない（#26）。配布は ZIP と dotnet tool（CLI）だけ |
| 初回の版 | `0.1.0-preview.1`（タグ `v0.1.0-preview.1`。#38） |

ライセンス表示は、`PackageLicenseExpression` に `LicenseRef-*` を入れられないため、`PackageLicenseFile=LICENSING.md` とする（`Directory.Build.props`）。
LICENSING.md は pack が自動では入れないので、CLI の `.csproj` で明示して同梱する（無いと NU5030）。BinaryMigrator・DatabaseConverter と同じ流儀。
SNI.runtime は含まれない（SqlClient を使わない。`ライセンス.md` の `sni` は `off`）。

### `release.yml`

`verify` ジョブが、配布 ZIP に加えて `dotnet pack` と nupkg の内容確認（必要なファイルがあること、pdb などが無いこと）を行い、nupkg を artifact「NuGet パッケージ」に残す。
PR・dry-run（`workflow_dispatch` の既定）・タグの push のどれでも、ここまでは動く。**この間は nuget.org へ何も送らない。**

`publish-nuget` ジョブ（先例は BinaryMigrator の `release.yml`）は、タグの push か `dry_run=false` の dispatch のときだけ動く（dry-run では動かない）。
`needs: verify`、`permissions: id-token: write`、artifact の nupkg の版（ファイル名と nuspec）がタグと一致することの確認、変数 `NUGET_ORG_USER` が空なら明確なエラーで止める確認、
`NuGet/login`（コミット固定）で 1 時間有効の API キーを受け取って `dotnet nuget push`、の順。長期の API キーは持たない。
`--skip-duplicate` は付けない。409 を何でも成功にすると、ID 予約やポリシーの不備を隠すため。同じ版の再実行（`already exists and cannot be modified`）だけを、警告つきで成功とみなす。

手元の確認は次のとおり。

```bash
dotnet pack src/VehicleVision.PleasanterTools.ExtensionsMigrator.Cli/VehicleVision.PleasanterTools.ExtensionsMigrator.Cli.csproj -c Release -p:Version=0.1.0-preview.1 -o <空のフィード用ディレクトリ>
dotnet tool install VehicleVision.PleasanterTools.ExtensionsMigrator --tool-path <空のディレクトリ> --add-source <フィード> --version 0.1.0-preview.1
<空のディレクトリ>/extensions-migrator --version
```

### nuget.org の準備（管理者の作業）

先例は BinaryMigrator の `release.yml` と `_documents/リリース手順.md`。

1. 変数 `NUGET_ORG_USER`（公開用の共用アカウントの nuget.org プロフィール名。メールアドレスではない）。
   組織の変数があり、可視性が all のため、リポジトリへの共有は要らないように見える（GitHub 画面の確認。**値の中身と実際の参照は未確認**。dry-run では参照されないので、公開時に初めて確かめられる）
2. nuget.org の Trusted Publishing のポリシー。**登録済みと担当者から申告があった（nuget.org の画面では未確認）。** 登録する内容は次のとおり。ポリシーは共用アカウントで作る（個人だと、その人が組織を抜けると無効になる）

   | 項目 | 値 |
   | --- | --- |
   | Package Owner | 組織 `vehiclevisionjp`（ID プレフィックス `VehicleVision` の予約が付くアカウント） |
   | Repository Owner | `vehiclevisionjp` |
   | Repository | `VehicleVision.PleasanterTools.ExtensionsMigrator` |
   | Workflow File | `release.yml` |
   | Environment | 空（環境を使うなら、ここと `publish-nuget` に同じ名前を入れる） |
   | Glob | `VehicleVision.PleasanterTools.ExtensionsMigrator`（完全一致） |

3. 未決定: DotNetClient の LGPL 全文の同梱（#38 の判断 2）。決まるまで、公開の前提としては扱わない

**nuget.org に出した版は削除できない**（非推奨にできるだけ）。タグも付け直せない。準備が無いままタグを作ると、GitHub Release は出て NuGet だけ失敗する（`publish` と `publish-nuget` は別ジョブ）。
初回は dry-run を両方（`release-run.yml` と `release.yml`）回し、artifact の nupkg を確認してからタグを作る。

## 公開前の確認

- `LICENSE`・`LICENSING.md`・`LICENSE-COMMERCIAL.md`・`NOTICE` が現状と合っている
- 配布物に設定ファイル・秘密・`_reference` が入っていない（`scripts/package.ps1` が検査する）
- 共有取得先を含め、Pleasanter の参照ソースや Git メタデータを配布に含めない。
  CI は参照ソースを取得しない。文書の根拠は確認した SHA・固定リンク・参照日で記録する。
  本体のポインタ更新 PR は不要（[参照ソース](../_reference/README.md)）
- 公開する場合は [ライセンス](ライセンス.md) の確認事項が済んでいる（権利確認・本体の非取り込み・依存の寛容性・正本の固有部分が実態と合っていること）
