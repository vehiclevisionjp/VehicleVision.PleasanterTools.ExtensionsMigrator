# 開発ガイド

## 前提

- .NET SDK 10.0.100 以降（`global.json`。全リポジトリで同じ値。`latestFeature` で新しいパッチへ進む）
- Node.js 24 以降（Markdown の検査用）
- PowerShell 7 と bash（スクリプト用）

## ビルドとテスト

```bash
dotnet restore --locked-mode
dotnet build --no-restore -c Release
dotnet test --no-build -c Release
npm ci --ignore-scripts && npm run lint:md
bash scripts/sync-agents.sh --check
bash scripts/reference-isolation-check.sh
```

依存を追加・更新したら `--locked-mode` を外して `dotnet restore` し、`packages.lock.json` を更新してコミットする。
依存は寛容ライセンス（MIT / BSD 系 / Apache-2.0）だけにし、追加時に一次情報でライセンスを確認して `NOTICE` を更新する。

## テストと fixture の決まり

- **fixture は合成データだけ。** 実環境の拡張の本文・名称・件数・パス・URL・ホスト名を使わない。
  公開リポジトリなので、社内の環境を推測できる値も入れない（`example.com` などの予約済みのドメインや、意味のない名前を使う）
- ファイルを扱うテストは、テストごとの一時フォルダの中だけで行い、Pleasanter の実際の `App_Data/Parameters/` を指さない
- API を扱うテストは、スタブか検証専用の環境だけを使う。**実環境の Pleasanter・Azure・DB へ接続しない**
- 認証情報（API キー・パスワード・Cookie・トークン）をテスト・ログ・fixture・Issue・PR・コミットに書かない。
  実機の検証で必要な値は、環境変数などの秘密の参照で渡す
- 実機での確認は、確認した範囲（Pleasanter の版・RDBMS・環境）だけを文書に書く。していないことは未検証と書く

## GUI（Avalonia）

- 技術は Avalonia（MIT）に決定（#14）。Reactor・Uno は、`Uno.Sdk.Extras` の EULA のため見送った
- **ビルド時のテレメトリは、設定なしで動かない。** Avalonia が推移的に引く `Avalonia.BuildServices`（ビルド時に匿名の利用情報を送る）は、`Gui.csproj` で直接参照にして `ExcludeAssets="all"` を付け、ビルドのターゲットとタスクを取り込まない（環境変数 `AVALONIA_TELEMETRY_OPTOUT` は不要）。このパッケージ参照を消す・`ExcludeAssets` を外すと、テレメトリが復活する
- **開発者ツール（`Avalonia.Diagnostics`・`AvaloniaUI.DiagnosticsSupport`）・Accelerate 系は使わない。** 使うなら Debug 専用の条件付き参照にして、配布物へ入れない。DataGrid・フォントのパッケージも、ライセンスを確認するまで足さない
- 起動の確認: `dotnet run --project src/VehicleVision.PleasanterTools.ExtensionsMigrator.Gui -c Release -- --smoke`（ウィンドウを開いて数秒後に閉じ、終了コード 0。描画の目視ではない）
- macOS・Linux は、ビルドだけ確認している（`-r linux-x64`・`-r osx-arm64`）。実行は未確認
- 依存を足したら、各パッケージのライセンスを、メタデータと同梱のライセンス文で確認し、`NOTICE` を更新する

## 規約を変える

共通規約の編集元は `.github/copilot-instructions.md`。変更後に `bash scripts/sync-agents.sh` で `AGENTS.md` を再生成する。

## Pleasanter の事実確認

Pleasanter 本体は Git で追跡しない参照専用ソースであり、実装へ取り込まない。
挙動を確かめる前に `bash scripts/sync-reference.sh` で `_reference/Implem.Pleasanter` を上流の `main` の先頭へ更新する。
`PLEASANTER_REFERENCE_DIR` があればその取得先を直接読む。文書には確認した完全なコミット SHA・ソースへの固定リンク・参照日を残す。
実機未検証ならその旨を残す（[参照ソース](../_reference/README.md)）。
